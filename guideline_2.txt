# 기술 명세서: Dialogue-based Medical HAC Policy Training Framework

## 1. 목표

이 프로젝트는 **User LLM, Medical LLM, Extractor LLM, Plug-in Policy**를 각각 교체 가능한 플러그인 모듈로 구성하여, 의료 Human-AI Collaboration 대화 환경에서 **사용자 상태를 추출하고, 그 상태에 따라 Medical LLM의 행동 전략을 선택하는 정책 모델**을 학습·평가하는 프레임워크를 구현한다.

전체 구조는 다음 흐름을 따른다.

```text
Case Info
   ↓
Medical LLM ── System Utterance ──> User LLM
   ↑                                  ↓
Action Prompt                    User Utterance
   ↑                                  ↓
Plug-in Policy ← User State ← Extractor LLM ← Dialogue History
```

Plug-in Policy는 초기에는 SFT로 학습하고, 이후 GRPO 기반 강화학습으로 개선될 수 있어야 한다.

# 4. 데이터 스키마

## 4.1 CaseInfo

```python
@dataclass
class CaseInfo:
    case_id: str
    scenario: str
    question: str
    options: dict[str, str]
    correct_answer: str | None = None
    expert_explanation: str | None = None
    metadata: dict[str, Any] = field(default_factory=dict)
```

---

## 4.2 DialogueTurn

```python
@dataclass
class DialogueTurn:
    speaker: Literal["system", "user", "medical"]
    text: str
    action: str | None = None
    user_state: dict[str, Any] | None = None
    metadata: dict[str, Any] = field(default_factory=dict)
```

---

## 4.3 DialogueHistory

```python
@dataclass
class DialogueHistory:
    case_id: str
    turns: list[DialogueTurn]

    def add_turn(self, speaker: str, text: str, **kwargs) -> None:
        ...

    def to_prompt(self) -> str:
        ...

    def to_messages(self) -> list[dict[str, str]]:
        ...
```

---

## 4.4 UserState

Extractor LLM은 dialogue history를 받아 다음과 같은 JSON을 출력한다.

```json
{
  "intent": "accept | challenge | ask_question | express_uncertainty | provide_evidence | other",
  "certainty": "certain | uncertain | neutral",
  "stance_toward_medical_llm": "agree | disagree | skeptical | confused | unknown",
  "medical_claims": [
    {
      "claim": "string",
      "confidence": "high | medium | low | unknown"
    }
  ],
  "user_noise": {
    "irrelevant_info": false,
    "contradiction": false,
    "emotional_expression": false
  },
  "key_facts": [
    "string"
  ],
  "missing_information": [
    "string"
  ],
  "summary": "short natural language summary"
}
```

주의점:

Extractor 출력은 반드시 JSON parse 가능해야 한다.
파싱 실패 시 retry 로직을 둔다.
retry 후에도 실패하면 fallback extractor를 사용한다.

# 5. 플러그인 인터페이스

## 5.1 BasePlugin

```python
class BasePlugin(ABC):
    @abstractmethod
    def name(self) -> str:
        pass

    @abstractmethod
    def load(self) -> None:
        pass
```

---

## 5.2 UserLLMPlugin

```python
class UserLLMPlugin(BasePlugin):
    @abstractmethod
    def generate_user_utterance(
        self,
        case_info: CaseInfo,
        dialogue_history: DialogueHistory,
        system_utterance: str,
        user_profile: dict[str, Any] | None = None,
    ) -> str:
        pass
```

역할:

Medical LLM의 system utterance를 보고 사용자 발화를 생성한다.

예시 구현:

```text
OpenAIUserLLM
AnthropicUserLLM
LocalUserLLM
MockUserLLM
```

---

## 5.3 MedicalLLMPlugin

```python
class MedicalLLMPlugin(BasePlugin):
    @abstractmethod
    def generate_medical_response(
        self,
        case_info: CaseInfo,
        dialogue_history: DialogueHistory,
        action_prompt: str,
    ) -> str:
        pass
```

역할:

Plug-in Policy가 고른 action prompt를 조건으로 받아 실제 의료 응답을 생성한다.

예시 action prompt:

```text
Accept the user's hypothesis and explain why it is clinically plausible.
Challenge the user's hypothesis and provide evidence-based reasoning.
Ask for missing clinical evidence before making a judgment.
Defer final judgment and summarize uncertainty.
```

---

## 5.4 ExtractorLLMPlugin

```python
class ExtractorLLMPlugin(BasePlugin):
    @abstractmethod
    def extract_user_state(
        self,
        case_info: CaseInfo,
        dialogue_history: DialogueHistory,
    ) -> dict[str, Any]:
        pass
```

역할:

대화 기록에서 user state를 JSON으로 추출한다.

필수 기능:

```text
1. JSON-only 출력
2. schema validation
3. retry on invalid JSON
4. fallback extraction
```

---

## 5.5 PolicyPlugin

```python
class PolicyPlugin(BasePlugin):
    @abstractmethod
    def select_action(
        self,
        case_info: CaseInfo,
        dialogue_history: DialogueHistory,
        user_state: dict[str, Any],
    ) -> dict[str, Any]:
        pass
```

반환값:

```json
{
  "action_id": "ACCEPT | CHALLENGE | ASK_EVIDENCE | DEFER | SUMMARIZE",
  "action_prompt": "natural language instruction for Medical LLM",
  "confidence": 0.72,
  "metadata": {}
}
```

---

## 7.2 1-step 흐름

```text
1. User LLM이 case info(답 알고 잇음), dialog history(1턴에서는 x) 보고 user utterance 생성
2. Dialogue History 업데이트
3. Extractor LLM이 dialogue history에서 user state 추출
4. Plug-in Policy가 user state를 보고 다음 action 선택
5. action prompt 생성
6. Medical LLM이 현재 action prompt에 따라 case info(답 모름), dialog history, user utterance 보고 system utterance 생성
7. 다음 turn으로 진행
```

# 8. SFT 학습

## 8.1 목적

SFT는 user state와 dialogue history를 보고 적절한 action을 예측하는 policy model을 학습한다.

입력:

```json
{
  "case_info": "...",
  "dialogue_history": "...",
  "user_state": {...}
}
```

출력:

```json
{
  "action_id": "CHALLENGE",
  "action_prompt": "Challenge the user's hypothesis and explain why..."
}
```

---

## 8.2 SFT 데이터 포맷

```json
{
  "id": "sft_001",
  "input": {
    "case_info": "...",
    "dialogue_history": [
      {
        "speaker": "medical",
        "text": "..."
      },
      {
        "speaker": "user",
        "text": "..."
      }
    ],
    "user_state": {
      "intent": "express_uncertainty",
      "certainty": "uncertain",
      "stance_toward_medical_llm": "agree"
    }
  },
  "target": {
    "action_id": "ASK_EVIDENCE",
    "action_prompt": "Ask for additional clinical evidence before accepting or challenging the user's hypothesis."
  }
}
```

---

## 8.3 Rule-based SFT Data Builder

초기에는 rule-based heuristic으로 SFT 데이터를 만들 수 있어야 한다.

예시:

```python
def label_action(user_state, case_info):
    if user_state["certainty"] == "uncertain":
        return "ASK_EVIDENCE"

    if user_state["stance_toward_medical_llm"] == "skeptical":
        return "SUMMARIZE"

    if has_wrong_claim(user_state, case_info):
        return "CHALLENGE"

    if has_correct_claim(user_state, case_info):
        return "ACCEPT"

    return "DEFER"
```

단, 이 rule policy는 baseline이자 bootstrapping 용도다. 최종 정책 성능을 보장하는 로직으로 간주하지 않는다.

# 9. GRPO 학습

## 9.1 목적

GRPO는 같은 상태에서 여러 action 후보를 샘플링하고, reward에 따라 상대적으로 좋은 action을 강화한다.

입력 상태:

```text
case_info + dialogue_history + user_state
```

출력 action:

```text
ACCEPT / CHALLENGE / ASK_EVIDENCE / DEFER / SUMMARIZE
```

---

## 9.2 GRPO rollout 구조

```text
For each case:
    reset environment
    for t in max_turns:
        extract user_state
        sample K actions from policy
        for each action:
            generate medical response
            generate user response
            compute reward
        compute group-relative advantage
        update policy
```

---

## 9.3 Reward 설계

Reward는 별도 모듈로 분리한다.

```python
class RewardModel:
    def score(
        self,
        case_info: CaseInfo,
        dialogue_history: DialogueHistory,
        user_state: dict[str, Any],
        selected_action: str,
        medical_response: str,
    ) -> float:
        ...
```

초기 reward 예시:

```text
+1.0  correct clinician decision을 적절히 수용함
+1.0  incorrect clinician decision을 적절히 반박함
+0.5  불충분한 정보 상황에서 근거 요청
+0.3  불확실성을 명확히 표현
-1.0  incorrect decision을 수용함, sycophancy
-1.0  correct decision을 부당하게 반박함, obstruction
-0.5  근거 없는 단정
-0.5  hallucinated medical claim
-0.1  unnecessary extra turn
```

Reward backend도 플러그인 가능하게 둔다.

```text
RuleReward
LLMJudgeReward
HybridReward
```

# 14. 중요한 설계 원칙

## 14.1 Policy는 Medical LLM을 직접 대체하지 않는다

Policy는 최종 의료 응답을 생성하지 않는다.

ㅡ```text
현재 user state에서 Medical LLM이 어떤 태도로 응답해야 하는지 action prompt를 선택한다.
```

즉,

```text
Policy → action prompt
Medical LLM → final medical response
```

구조를 유지해야 한다.

---

## 14.2 Extractor와 Policy를 분리한다

Extractor는 대화에서 상태를 추출한다.

Policy는 그 상태를 보고 행동을 선택한다.

```text
Dialogue History → Extractor → User State → Policy → Action
```

Extractor 내부에서 action을 결정하지 않게 한다.

---

## 14.3 Rule-based mapping은 baseline일 뿐이다

초기에는 rule로 action을 만들 수 있지만, 최종 구조에서는 policy model이 학습을 통해 action을 선택해야 한다.

```text
RulePolicy = debugging / bootstrap baseline
SFTPolicy = supervised initialized policy
GRPOPolicy = reinforcement-learned policy
```

---

## 14.4 모든 중간 결과를 저장한다

디버깅과 논문 분석을 위해 다음 값은 반드시 저장한다.

```text
case_info
dialogue_history
system_utterance
user_utterance
user_state
selected_action
action_prompt
medical_response
reward

```

CHALLENGE
ASK_EVIDENCE

  "confidence": float,
  "metadata": {}
}

The extractor output must be valid JSON and conform to a UserState schema.

Make the code clean, typed, testable, and easy to extend.

Do not hard-code specific LLM providers into the core environment. Provider-specific logic must stay inside plugins.

Use Python 3.11+.
Use pydantic or dataclasses for schemas.
Use PyYAML for config loading.
Use JSONL for rollout logs.
```
